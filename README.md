# 반짝반짝 수학 탐험대 — 여러 학교용

학교 이름·반·번호로 참여하는 초등학교 1학년 단원별 퀴즈입니다. 화면은 **GitHub Pages**, 출제·채점·저장은 기존 **Google Apps Script와 스프레드시트**가 담당합니다. 학생 Google 로그인과 Supabase 설정은 필요 없습니다.

## 선생님이 할 일: GitHub Pages 켜기

현재 저장소: https://github.com/t1ssueJung/math-1

1. ZIP을 내려받았다면 압축을 풀고, 안의 파일들을 저장소 최상위에 올립니다. `index.html`이 저장소 첫 화면의 파일 목록에 보여야 합니다. ZIP 파일 자체나 그 위의 폴더 한 겹을 올리지 마세요.
2. GitHub의 **Settings → Pages**를 엽니다.
3. **Build and deployment → Source → Deploy from a branch**를 선택합니다.
4. **Branch: main / 폴더: /(root)**를 선택하고 **Save**를 누릅니다.
5. 배포가 끝나면 Pages 화면의 **Visit site**를 눌러 확인합니다.

배포가 완료되면 예상 학생 주소는 `https://t1ssuejung.github.io/math-1/`입니다. 설정 전에는 열리지 않을 수 있습니다.

이미 준비한 기록 서버와 연결된 `config.js`를 포함했습니다. 학교 이름은 학생이 직접 입력합니다. 교사 비밀번호를 GitHub 파일에 쓰지 마세요.

## 사용법

- 학생: 학생 시작 → 학교의 정식 이름 → 반·번호 → 학기·단원 → 시작.
- 같은 학교는 띄어쓰기가 달라도 한 학교로 처리합니다. `세천초`와 `대구세천초등학교`처럼 줄임말이 다르면 다른 학교가 되므로 정식 이름을 안내하세요.
- 새 학교·새 반은 첫 응시 때 자동 등록됩니다. 반 수와 재응시 횟수에 프로그램상의 제한은 없습니다.
- 10문제, 4지선다, 첫 오답 힌트와 재도전, 두 번째 오답 정답·풀이를 유지했습니다.
- 교사: 선생님 → 조회할 학교의 정식 이름과 기존 공통 비밀번호 입력.
- 로그인한 학교의 반·학생 통계와 CSV를 볼 수 있습니다. CSV 첫 열에 학교 이름이 들어갑니다.
- **공통 비밀번호는 기존처럼 모든 참여 학교에서 공유합니다.** 학교별 별도 비밀번호/교사 계정 인증 방식은 아닙니다. 공통 비밀번호를 아는 교사는 다른 학교 이름으로도 로그인할 수 있으므로, 참여 교사에게만 비밀번호를 알려 주세요.
- 좌측 상단 로고는 첫 화면으로 돌아갑니다.

## 교육과정

1학기: 9까지의 수 / 여러 가지 모양 / 덧셈과 뺄셈 / 비교하기 / 50까지의 수.

2학기:

| 단원 | 대표 출제 내용 |
|---|---|
| 1. 100까지의 수 | 수의 순서·크기, 묶음·낱개, 60·70·80·90 읽기, 짝수·홀수 |
| 2. 덧셈과 뺄셈(1) | 세 수 계산, 10이 되는 더하기, 10에서 빼기, 10 만들어 더하기 |
| 3. 모양과 시각 | 네모·세모·동그라미와 특징, 정각·30분 |
| 4. 덧셈과 뺄셈(2) | 한 자리 수끼리 받아올림 덧셈, 십몇에서 받아내림 뺄셈 |

'전체 복습'은 학기의 계산 단원을 모두 배운 뒤 선택합니다. 교과서의 모든 조작·그리기 활동을 구현한 앱은 아닙니다.

## 기존 기록 보존

- 학교 정보가 없던 기존 기록은 **대구세천초등학교**로 해석합니다. 기존 행에 학교 이름을 덮어쓰거나 점수를 바꾸지 않습니다.
- 기존 세 시트의 오른쪽에 `school_name` 열을 자동으로 추가합니다. 기존 응시·답안·점수와 옛 화면에서 진행 중인 제출을 보존합니다.
- 수정 전 2학기 2·4·6단원 기록은 `(수정 전 범위)` 표시를 유지합니다.
- 학교 이름을 입력하지 않는 기존 화면은 대구세천초등학교로 처리합니다.
- 학생 스프레드시트의 공개 범위는 바꾸지 않습니다. 학생에게는 GitHub Pages 주소만 안내하세요.

## 파일 구성

- `index.html`, `style.css`, `app.js`, `config.js`: GitHub Pages 화면.
- `backend/Code.gs`, `backend/Index.html`: Apps Script 기록 서버의 소스 사본.
- `tests/`: 출제·채점·기존 데이터 보존·학교 구분·연결 메시지 검증.

이 저장소의 `backend/` 파일은 GitHub에 올린다고 자동 설치되지 않습니다. 현재 사용 중인 기록 서버에는 학교 구분과 GitHub 연결 기능을 별도로 반영했습니다.

서버 소스를 나중에 수정할 때는 Apps Script의 Code.gs/Index.html을 교체하고, **배포 → 배포 관리 → 기존 배포 수정 → 새 버전**을 선택합니다. 기존 스크립트 속성 `SPREADSHEET_ID`, `TEACHER_PASSWORD`를 유지하세요.

새 기록 서버를 직접 만들 때는 스프레드시트의 **확장 프로그램 → Apps Script**에서 두 파일을 넣고 비밀번호 속성을 등록한 뒤 `setup`을 실행합니다. `SPREADSHEET_ID` 속성에 저장할 스프레드시트 ID를 직접 지정할 수도 있습니다. 비밀번호·개인 키는 소스에 넣지 않습니다.

다른 GitHub 사용자나 별도 도메인으로 옮기면 서버의 스크립트 속성 `PAGES_ORIGINS`에 허용할 화면의 origin을 쉼표로 나누어 설정합니다. 경로는 제외합니다. 예: `https://본인계정.github.io`. 기본 허용 목록은 현재 저장소의 Pages origin과 로컬 검증 주소뿐입니다. `config.js`의 `backendUrl`도 새로 배포한 실제 공개 `/exec` 주소로 바꾸세요.

## 검증과 운영 범위

- 11개 단원 × 3개 연산 설정 × 30회 = 9,900문제의 범위·정답·보기를 검사했습니다.
- 전체 HTML 흐름의 힌트·재도전·풀이·서버 채점·중복 제출·저장·교사 통계·CSV·로고 이동을 검사했습니다.
- 학교 이름 유효성, 같은 반·번호의 학교 구분, 기존 행 보존, 학교별 세션 조회를 검사했습니다.
- 연결은 허용된 부모 origin·난수 nonce·응답 source·요청 ID를 확인합니다. 교사 비밀번호를 URL에 넣지 않습니다.
- Google 서버와 연결한 별도 웹 화면에서 테스트 학교 10문제 풀이·7/10점 저장·학교별 교사 조회·CSV 실제 다운로드를 확인했습니다.
- 학생 로그인은 필요 없지만 Google Apps Script/스프레드시트 서비스 및 실행 할당량을 사용합니다. 학교 수·응시 횟수에 앱 자체 제한이 없다는 것이 서비스 사용량이 무제한이라는 뜻은 아닙니다.
- 학생이 입력한 학교 이름 자체는 학교 인증 수단이 아닙니다.

개발용 검증: Node.js 24에서 `npm ci`, `npm test`.
